# Отчет по лабораторной работе 8

## Тема
Приложение для ведения журнала покупок с использованием SQLite.

## Постановка задачи
Разработать приложение для ведения журнала покупок с базой данных SQLite. База данных должна содержать таблицу `transactions` со следующими полями:
- `transaction_id`: PRIMARY KEY, AUTOINCREMENT
- `item_name`: TEXT, NOT NULL
- `quantity`: INTEGER, NOT NULL, больше 0
- `price_per_unit`: REAL, NOT NULL, больше 0
- `purchase_date`: TEXT, DEFAULT CURRENT_TIMESTAMP

Приложение должно предоставлять следующие функции:
1. Запись покупки (с автоматической записью текущей даты и времени)
2. Показать все покупки
3. Вычислить общую стоимость покупок
4. Найти покупки по конкретной дате
5. Удалить покупку по ID

## Структура проекта
- `main.py` — основной скрипт с классом `PurchaseLog` и функциями работы с базой данных.
- `purchases.db` — база данных SQLite, создаваемая автоматически при первом запуске.

## Описание реализации

### Класс `PurchaseLog`
Класс инкапсулирует всю логику работы с базой данных покупок.

#### `__init__(self, db_name='LR 8/purchases.db')`
```python
def __init__(self, db_name='LR 8/purchases.db'):
    self.db_name = db_name
    self.conn = sqlite3.connect(db_name)
    self.cursor = self.conn.cursor()
    self._create_table()
```
Инициализирует подключение к базе данных SQLite, создает курсор и вызывает метод создания таблицы.

#### `_create_table(self)`
```python
def _create_table(self):
    self.cursor.execute('''
        CREATE TABLE IF NOT EXISTS transactions (
            transaction_id INTEGER PRIMARY KEY AUTOINCREMENT,
            item_name TEXT NOT NULL,
            quantity INTEGER NOT NULL CHECK(quantity > 0),
            price_per_unit REAL NOT NULL CHECK(price_per_unit > 0),
            purchase_date TEXT DEFAULT CURRENT_TIMESTAMP
        )
    ''')
    self.conn.commit()
```
Создает таблицу `transactions` с указанными полями и ограничениями. Используется `CREATE TABLE IF NOT EXISTS` для предотвращения ошибок при повторном запуске.

#### `record_purchase(self)`
Функция 1: Запись покупки
- Запрашивает у пользователя название товара, количество и цену за единицу.
- Выполняет валидацию входных данных (проверка на пустые значения и положительные числа).
- Автоматически записывает текущую дату и время с помощью `datetime.now()`.
- Вставляет запись в таблицу и выводит ID созданной транзакции.

#### `show_all_purchases(self)`
Функция 2: Показать все покупки
- Выполняет SELECT-запрос для получения всех записей, отсортированных по дате (новые сначала).
- Форматирует вывод в виде таблицы с колонками: ID, Товар, Количество, Цена/ед., Дата покупки, Сумма.
- Выводит сообщение, если журнал пуст.

#### `calculate_total_cost(self)`
Функция 3: Вычислить общую стоимость покупок
- Использует SQL-функцию `SUM(quantity * price_per_unit)` для вычисления общей стоимости.
- Обрабатывает случай, когда в таблице нет записей (возвращает 0.0).

#### `find_purchases_by_date(self)`
Функция 4: Найти покупки по конкретной дате
- Запрашивает у пользователя дату в формате YYYY-MM-DD.
- Валидирует формат даты с помощью `datetime.strptime()`.
- Использует SQL-функцию `DATE()` для сравнения дат.
- Выводит все покупки за указанную дату и общую сумму за день.

#### `delete_purchase_by_id(self)`
Функция 5: Удалить покупку по ID
- Запрашивает ID транзакции для удаления.
- Проверяет существование записи перед удалением.
- Показывает информацию о покупке и запрашивает подтверждение.
- Удаляет запись только после подтверждения пользователем.

#### Поддержка контекстного менеджера

Главная функция создает экземпляр `PurchaseLog` и предоставляет интерактивное меню для работы с журналом покупок. Использует контекстный менеджер для автоматического закрытия соединения.

## Особенности реализации
- **Валидация данных**: Проверка корректности ввода на всех этапах (пустые строки, отрицательные числа, формат даты).
- **Обработка ошибок**: Использование блоков `try/except` для обработки исключений при работе с базой данных и пользовательским вводом.
- **SQL-инъекции**: Использование параметризованных запросов (`?`) для предотвращения SQL-инъекций.
- **Ограничения базы данных**: Использование `CHECK` для обеспечения целостности данных на уровне БД.
- **Удобный интерфейс**: Форматированный вывод таблиц и понятные сообщения об ошибках.
