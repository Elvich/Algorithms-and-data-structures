## Задание №3: Контрольные вопросы

**1. Что такое PEP 8 и почему важно следовать его рекомендациям?**
PEP 8 — это официальное руководство по стилю кодирования для языка Python. Следовать его рекомендациям важно для того, чтобы код был максимально читаемым, понятным и единообразным, что особенно критично для командной разработки и поддержки кода другими разработчиками.

**2. Для чего используются flake8 и black? В чем их основные отличия и как они дополняют друг друга?**
- `flake8` — это линтер, инструмент статического анализа, который проверяет код на соответствие стандартам PEP 8, находит неиспользуемые переменные, импорты и другие логические ошибки.
- `black` — это бескомпромиссный форматер кода, который автоматически переписывает файлы так, чтобы они соответствовали стандартам стиля (отступы, кавычки и т.д.).
- **Отличия:** `black` сам меняет код (форматирует), а `flake8` лишь указывает на ошибки.
- **Как дополняют:** Сначала используется `black` для автоматического приведения кода в порядок, а затем запускается `flake8` для нахождения того, что форматер не исправляет (например, неиспользуемые импорты или сложные логические баги).

**3. Что такое mypy и как он используется для статического анализа кода?**
`mypy` — это инструмент статического анализа типов для Python. Он анализирует код (не выполняя его) и проверяет, соответствуют ли используемые типы данных тем, что указаны в аннотациях типов (Type Hints). Это помогает находить потенциальные баги, связанные с неверной передачей типов, до запуска программы.

**4. Объясните концепцию Docstrings. Где они размещаются и для чего используются?**
Docstrings (строки документации) — это строковые литералы (обычно заключенные в тройные кавычки), которые пишутся сразу после определения модуля, функции, класса или метода. Они используются для документирования того, что делает данный объект, какие аргументы он принимает, что возвращает и какие исключения может вызвать. Они доступны во время выполнения через атрибут `__doc__`.

**5. Что такое Sphinx и для чего он нужен в Python-разработке?**
Sphinx — это мощный генератор документации, который преобразует исходные файлы (в форматах reStructuredText или Markdown) и автоматически извлеченные из Python-кода Docstrings в читаемые форматы, такие как HTML или PDF. Он является стандартом де-факто для создания документации к Python-проектам.

**6. Какие шаги необходимо выполнить для генерации HTML-документации с помощью Sphinx?**
1. Установить Sphinx (`pip install sphinx`).
2. Инициализировать проект в директории `docs` с помощью `sphinx-quickstart`.
3. Настроить конфигурацию в `conf.py` (подключить `autodoc`, прописать пути к коду).
4. Сгенерировать файлы `.rst` для модулей проекта через `sphinx-apidoc`.
5. Добавить сгенерированные файлы в дерево `index.rst`.
6. Выполнить команду `make html` (или `sphinx-build -b html . _build/html`) для генерации HTML-страниц.

**7. Для чего нужен файл conf.py в проекте Sphinx?**
Это главный конфигурационный скрипт (написанный на Python), в котором задаются настройки для генерации документации. Там указываются метаданные проекта (название, версия, автор), подключаемые расширения (например, для авто-документации), тема оформления (например, `sphinx_rtd_theme`) и настройки путей (где искать Python-модули).

**8. В чем основные преимущества Poetry (или Rye) по сравнению с requirements.txt?**
- Декларативное управление: все зависимости (включая зависимости для разработки) описываются в одном файле `pyproject.toml`.
- Наличие lock-файла (`poetry.lock`), который жестко фиксирует версии не только прямых, но и транзитивных зависимостей, обеспечивая 100% воспроизводимость.
- Автоматическое создание виртуальных окружений и управление ими.
- Встроенные возможности для публикации пакетов.

**9. Почему важно управлять зависимостями в Python-проектах?**
Разные проекты могут требовать разные версии одних и тех же библиотек. Без эффективного управления зависимостями (с помощью виртуальных окружений и lock-файлов) код, работающий на компьютере одного разработчика, может сломаться на другом компьютере или на сервере из-за несовпадения версий. Управление зависимостями гарантирует воспроизводимость и стабильность работы проекта.
