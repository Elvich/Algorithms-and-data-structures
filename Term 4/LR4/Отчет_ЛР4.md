## Задание №3: Контрольные вопросы

**1. Что такое PEP 8 и почему важно следовать его рекомендациям?**
PEP 8 — это официальное руководство по стилю кодирования для языка Python. Следовать его рекомендациям важно для того, чтобы код был максимально читаемым, понятным и единообразным. Это сильно облегчает поддержку кода в будущем и процесс командной разработки.

**2. Для чего используются flake8 и black? В чем их основные отличия и как они дополняют друг друга?**
- `flake8` — это линтер, инструмент статического анализа, который лишь *проверяет* код на соответствие PEP 8 и находит логические ошибки (например, неиспользуемые переменные).
- `black` — это форматер кода, который *автоматически переписывает* файлы так, чтобы они соответствовали стандартам стиля (отступы, перенос строк).
- **Как дополняют:** Сначала используется `black` для автоматического приведения кода в порядок, а затем запускается `flake8`, чтобы подсветить то, что форматер не вправе исправлять (слишком длинные текстовые строки, неиспользуемые импорты и т.д.).

**3. Что такое mypy и как он используется для статического анализа кода?**
`mypy` — это инструмент статического анализа типов для Python. Он парсит код и проверяет, соответствуют ли используемые типы данных тем, что указаны в аннотациях типов (Type Hints). Это помогает находить потенциальные баги до выполнения (раньше, чем они упадут в рантайме).

**4. Объясните концепцию Docstrings. Где они размещаются и для чего используются?**
Docstrings (строки документации) — это строковые литералы (обычно заключенные в тройные кавычки), которые пишутся сразу после определения модуля, функции, класса или метода. Они используются для документирования того, что делает данный объект, какие аргументы он принимает, что возвращает. В отличие от комментариев, они доступны во время выполнения через атрибут `__doc__` и могут парситься генераторами вроде Sphinx.

**5. Что такое Sphinx и для чего он нужен в Python-разработке?**
Sphinx — это мощный инструмент-генератор документации. Он берет исходные файлы (например, `.rst` или `.md`) и автоматически извлекает Docstrings из Python-кода, чтобы собрать из них удобные веб-страницы (HTML) или PDF. Он является стандартом де-факто для документации в Python (даже сама документация по Python написана на нем).

**6. Какие шаги необходимо выполнить для генерации HTML-документации с помощью Sphinx?**
1. Установить Sphinx (`pip install sphinx sphinx-rtd-theme`).
2. Инициализировать проект в директории `docs` с помощью `sphinx-quickstart`.
3. Настроить конфигурацию в `conf.py` (подключить `autodoc` и прописать `sys.path.insert()`).
4. Сгенерировать файлы `.rst` для модулей проекта (через `sphinx-apidoc`).
5. Добавить сгенерированные файлы в `index.rst`.
6. Выполнить команду сборки `make html`.

**7. Для чего нужен файл conf.py в проекте Sphinx?**
Это главный конфигурационный скрипт, написанный на Python. Там хранятся метаданные документации (имя проекта, версия, автор), подключаемые расширения (например, для парсинга Google-style docstrings `sphinx.ext.napoleon`), тема оформления и настройки путей к исходникам.

**8. В чем основные преимущества Poetry (или Rye) по сравнению с requirements.txt?**
- Декларативное описание в едином `pyproject.toml` вместо нескольких `requirements.txt` (для dev и prod).
- Автоматическое использование lock-файла (`poetry.lock`), который надежно фиксирует версии не только прямых, но и всех транзитивных (вложенных) зависимостей.
- Инструмент сам управляет созданием и активацией виртуального окружения проекта.
- Встроенный функционал для сборки и публикации пакета в PyPI.

**9. Почему важно управлять зависимостями в Python-проектах?**
Чтобы гарантировать стопроцентную воспроизводимость окружения. Без жесткой фиксации версий библиотек ваш код может работать на одном компьютере, но выдать ошибку на другом (или на сервере), если там установится более новая версия библиотеки с изменениями, ломающими обратную совместимость. Управление зависимостями гарантирует стабильность проекта во времени и пространстве.
